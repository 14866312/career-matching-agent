# 岗位画像数据说明（backend/data/career-data.json）

本文档描述岗位画像数据的生成方式、字段结构与处理规则，供 matching-engineer、viz-builder、quality-reviewer
和主 Agent 对照使用。当前数据版本 **career-1.3**，等级规则 **level-1.1**，标签字典 **tags-1.2**。

## 1. 生成方式与可重复性

    .venv/Scripts/python.exe scripts/build_data.py

脚本只读读取 competition/岗位样例数据.xls（不写回原始文件），输出两个文件：

- backend/data/career-data.json：机器可读数据契约，内置 42 项自检，audit.checks_failed 必须为空。
- docs/职业数据审核.md：逐画像**证据摘要**（标签 / 维度 / 等级 / 等级来源 / 票数 / 证据来源与引用），
  由 review_digest() 生成，tests/test_data.py 会校验它与 JSON 同步。标题写明“待主控审定”：
  该文件只是脚本推导结果，不代表已经人工或主控审定，签署 PINNED 后才是交付口径。

可重复性：同一原始文件连续两次重建，career-data.json 的 SHA256 完全一致；原始 XLS 哈希不变，证据见 docs/验收产物/数据可复现性.json。
tests/test_data.py 的 test_rebuild_is_deterministic 校验两次构建结果一致，
test_generated_file_matches_rebuild 校验仓库中的 JSON 与当前脚本重建结果一致。

## 3. jobs[] 岗位画像

| 字段 | 说明 |
|---|---|
| id / name / family | 稳定 ID、岗位名、岗位族 |
| record_type | 固定为 typical_profile（与招聘记录区分） |
| level | 画像级别：初级能力基线 |
| summary / monogram / color | 前端展示用摘要与配色 |
| requirements | 必需项：技能 + 通用素质 + 达标证书，全部进入基础分分母 |
| preferred | 优先项：技能优先项 + 证书优先项，均不进分母 |
| certificates | 证书维度矩阵：7 个证书标签的 required / preferred / unmentioned 与逐条提及分类 |
| dimensions | 三维标签的 required / preferred / unmentioned 名单 |
| certificate_note | 证书口径说明 |
| profile_basis / evidence_summary | 归纳基线与候选/支持样本统计 |
| samples | 关联招聘记录（用于城市与薪资筛选） |
| version | 画像版本 |

requirements[] 中的技能与素质条目：

| 字段 | 说明 |
|---|---|
| tag_id / label / dimension | 规范标签 ID、展示名、维度 |
| requirement | 固定 required |
| required_level | 1-3，由样本措辞聚合或默认基线得到 |
| level_source | level_rule（有明确措辞）或 default_baseline（无明确措辞，默认 2） |
| level_rule_version | level_rule 时为 level-1.1，default_baseline 时为 null |
| level_basis | 人类可读依据；默认基线一定包含“默认”二字，供匹配层识别来源 |
| level_wording_rule / level_aggregation | 措辞规则与聚合规则原文 |
| level_observations | 参与众数的逐等级票数，如 {"2": 4, "3": 18} |
| level_observation_sources | 参与众数的来源 ID（每个来源最多出现一次，可复核计票） |
| level_preference_observations | 只出现在“优先/加分”措辞里的等级计数，不参与众数 |
| level_preference_sources | 上述优先措辞来源 ID，与 level_observation_sources 无交集 |
| level_observed_samples / level_samples | 计票来源数与前 3 条样本（source_id + level + wording） |
| level_witness | 决定等级的样本（source_id + wording + level），必定出现在 evidence 中且非优先措辞 |
| evidence[] | {source_id, quote, offset, level, wording, preference}，最多 3 条，逐字来自原文句子 |
| evidence_count / evidence_shown | 可用证据总数 / 展示条数 |

requirements[] 中的证书条目（当前只有 testing 的 CET-4）：dimension = certificates、requirement = required、
required_level = 1、level_source = binary_requirement、level_rule_version = null、
level_basis 说明“二元要求”，另带 mention_count / mandatory_mention_count / classifications /
evidence（逐条分类 required / preferred / mentioned / unmentioned）。

preferred[] 条目：tag_id、label、dimension、requirement = preferred、required = false、
required_level = null（不显示伪造等级）、mention_count / mandatory_mention_count（证书）、
evidence[]、selection_basis。技能优先项也在该列表中；推荐层的技能筛选读取 required 与 preferred 的并集。

samples[] 条目：id、record_type = recruitment_record、job_code、company、city、city_raw、address、
salary{min,max,period,period_source,currency,unit_label,extra_months,raw,basis}、updated_raw、url、
source_id、sample_only、version{index,distinct_versions,content_sha256,order_basis}、level_evidence、
data_quality{detail_chars,detail_incomplete,missing_fields,salary_parsed,salary_period,updated_has_year,
updated_note,duplicate_rows_merged}。

sources[row-N] 条目：id、sheet、row、job_code、url、title、company、
company_meta{industry,size,financing_stage,profile_present,missing,note}、detail（清理后的完整原文）、
detail_chars、salary_raw、updated_raw、markers（结构化状态标记）、raw_sha256、content_sha256、
duplicate_rows_merged（被合并的原始行号）、version、used_by_profile。

## 4. 处理规则（对应交接的 8 条数据问题与主控裁决）

1. **原始全字段去重**：先用原始字段签名判重（清理前的原始值），再清理展示标记。清理后的写法差异不会
   导致两条不同记录被合并；被合并的行号记录在 sources[].duplicate_rows_merged，合计数见
   audit.dedupe_merged_rows_total（当前 527，与 pandas 独立重算一致）。
2. **同编码不同内容版本索引**：同岗位编码但内容不同的记录不合并，全部进入 code_versions，每条版本都保留
   原始行号、raw_sha256 与 content_sha256——即使清理后的 content_sha256 相同，原始哈希与行号也照常保留，
   只把原因标为 duplicate_content_version。同一编码最多由一个画像引用一条版本（避免推荐重复职位），
   同一份正文也不会出现在两个画像中（audit.content_duplicate_skips）。版本顺序只按原始行号，
   不推断时间新旧；高级版本不用于初级画像证据。
3. **未知薪资保留**：面议与未解析出区间的记录保留在 samples 中，只有调用方真正启用薪资筛选时才由匹配层
   排除。按小时/年/周计薪属于另一种计薪周期，不作为“未知”，不进入样本池，跳过次数见
   audit.salary_filter.unsupported_candidate_skips。日薪与月薪分别保存与筛选，不做隐式换算。
4. **等级按真实明确措辞 + 主控裁决的计票规则**：
   - 措辞只取同一句内标签出现位置之前最近的「熟练=3 / 熟悉=2 / 了解=1」；等级词与标签提及之间不得出现
     分句符号（全角逗号、句号、分号、换行）或编号列表标记（如“3. ”），否则该句不产生观测。
     掌握、精通、扎实、良好、使用、基础、理解、初步等泛词一律不映射。
   - 一个支持样本对同一标签只计一票（按该来源最早一条明确措辞计入），防止同一来源多次提及重复计票。
   - 写成“优先/加分”措辞的样本不参与必需等级众数，只记录在 level_preference_observations /
     level_preference_sources 中供复核。
   - 众数并列时取较弱等级；没有任何非优先明确措辞时才使用默认等级 2 并标为 default_baseline。
   - 每条要求都带 level_observations、level_observation_sources、level_samples 与 level_witness，
     且 witness 一定位于 evidence 中，可逐条复核计票。
5. **优先技能真正 preferred**：样本以“优先/加分/更佳/更优/可选/增加竞争力”措辞提及的非必需技能写入
   jobs[].preferred（dimension = skills），不进入必需分母，也不再只写 dimensions。
6. **必需证书准确分类**：证书提及先按上下文分类：出现硬性措辞（必须/须持/需持/须通过/需通过/需具备/
   硬性/强制）或位于语言、证书类章节（【语言能力】【语言要求】【证书要求】【资质要求】【认证资质】
   【资格证书】等）为 required；与提及位置更近的“优先/加分”措辞为 preferred；其余为 mentioned。
   同一画像内不少于两份不同来源样本给出 required 提及才把证书列为必需，并写入 requirements 的证书维度；
   否则列为优先项；未出现为未提及。公司主体认证、专利、著作权、检测报告等上下文一律剔除
   （COMPANY_CREDENTIAL_RE），未提及不补造证书。
7. **排除高级证据**：记录级排除 3 年以上、3-5 年、资深、架构师、技术专家、项目负责人、高级×× 等措辞
   （audit.seniority_filter，当前 131 条）；1-3 年、应届、经验不限保留。句子级同样过滤，
   高级句子既不作为证据也不产生等级观测。
8. **标签词典不泛化**：SQL 只识别 “SQL”（不再把“数据库”当作 SQL，别名同步移除）；接口测试不再用
   Postman / Fiddler / JMeter 表示；自动化测试不再用 Selenium / Appium 表示。工具名与类别词不进入别名表
   （FORBIDDEN_ALIASES 由自检强制）。
9. **SQL / MySQL 按 ASCII token 匹配**：这两个标签的 pattern 用 (?<![A-Za-z0-9]) … (?![A-Za-z0-9]) 包住，
   与 backend/app/llm.py::mentions_alias 完全同一口径。因此 MySQL / NoSQL / PostgreSQL 都不算 SQL，
   “SQL Server”“熟悉 SQL 语句”式表达里的独立 SQL 才算；反过来 MySQLProxy 这类拼接词也不算 MySQL。
   旧口径把 MySQL 句子同时计入 sql 和 mysql，既抬高了候选记录打分，也让 sql 等级被 mysql 句子带偏。

## 5. 追溯结构

### 5.1 sources

键为 row-N（N = XLS 原始行号，含表头偏移），保留岗位编码、来源地址、原始标题、清理后完整正文、薪资原文、
更新日期原文以及 raw_sha256 / content_sha256。每条要求与证书证据都用 source_id + 逐字 quote 指回这里。

### 5.2 code_versions

    岗位编码 -> {
      distinct_versions, raw_rows, claimed_by, titles, order_basis,
      versions: [{version_index, row, title, content_sha256, raw_sha256, retained,
                  source_id?, reason}],
      note
    }

reason 取值：selected_for_profile:<id>（该版本被引用）、other_title_version（同编码的另一条内容不同、
标题不同）、duplicate_content_version（清理后正文与已保留版本相同，但原始行号与原始哈希仍保留）、
senior_requirement_version_not_used（高级版本不用于初级画像）、not_selected_for_junior_baseline
（其余未入选版本）。当前索引覆盖 240 个编码、252 个版本，其中 12 个编码存在标题不同的内容版本
（如“实施工程师 / 技术支持工程师”“测试工程师 / 硬件测试”），说明岗位编码不能当作稳定职位 ID。

## 7. 下游接口约定

- **匹配层**：requirements 中每条 required_level ≥ 1；证书条目 required_level = 1 且 dimension = certificates，
  增强分按二元计算（1/0），不按等级折算。preferred 行满足 requirement = preferred、required = false，
  匹配层现有 _is_preferred_row 逻辑即视为优先项，不进分母。
- **技能筛选**：required_tags 与 preferred_tags 的并集，因此技能优先项也会被技能筛选接受
  （与 matching 顶部 SKILL_FILTER_RULE 说明一致）。
- **前端**：/api/jobs 白名单已包含 requirements、preferred、certificates、dimensions。显示注意：
  证书必需项也出现在 requirements 中，RequirementItem 的“要求等级 1”对证书只是结构占位，
  建议前端在 level_source = binary_requirement 时改显示“二元要求”（数据侧已给出 level_basis 说明）。

## 8. 主控裁决与已知限制

1. **生产契约已由主控复核更新**：tests/test_matching.py 的 PINNED_PROFILES / PINNED_PREFERRED 已对齐 career-1.3，
   主控审定依据见 docs/数据审核.md。自动生成的证据摘要保留待审定标记，独立审定记录以该文件为准。
   冻结画像（FROZEN_PROFILES 手算 27 例）及其独立期望值保持不变。
2. **评分影响**：testing 的基础分分母由 6 变为 7（CET-4 成为必需证书）；frontend 的四项技能、
   cpp 的数据结构/算法、support 的故障排查/技术文档等级为 3，implementation 的软件部署为 1；
   **career-1.3 起 testing 的 SQL 由 3 降为 2（原 3 级投票来自只写 mysql 的 row-765）**。
   增强分会相应变化，需要按新等级重算期望值。
3. 证书批次较小：每个画像只有 40 条支持样本，证书结论随样本选择变化；逐条分类与来源已保留在
   certificates 与 audit 中，便于复核。
4. 部分样本缺少公司类型、公司详情等元信息，按缺失处理，不补造；更新日期缺年份时不推断年份。
5. 换岗路径为人工整理的条件性建议，不承诺可直接转岗；阶段节点不作为独立推荐岗位。
6. **career-1.3 的样本集变化**：修正 SQL 边界后，java 与 implementation 的候选打分口径变化
   （原先只写 MySQL 的句子同时贡献 sql + mysql 两个计数），各替换 10 条 / 4 条支持样本；
   testing / frontend / cpp / support 的样本集不变。因此薪资周期统计（月 203→201、日 34→36）
   与个别优先项证据（implementation 的 java / linux / networking）也随之变化。主控接受按修正后的
   SQL 候选规则重新选择样本，不冻结旧错误口径产生的样本集合。
7. 优先措辞按整句保守判定，可能把同句中未被“优先”直接修饰的标签也归入补充项；
   画像是样本归纳基线，不是逐条招聘要求的完整语义解析。
8. 薪资解析不支持所有混合单位写法（如 15k-25k、8千-1.2万），当前入选样本未发现这些写法；
   新数据须先复核，不将解析失败当作零薪资。SQL/MySQL 边界规则也不能推广为所有标签已采用统一分词。
