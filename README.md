# 大学生职业规划智能体

[![CI](https://github.com/14866312/career-matching-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/14866312/career-matching-agent/actions/workflows/ci.yml)

一个帮大学生看清「我离目标岗位还差多少」的小工具。

你把自己会的技能告诉它（上传简历，或者手动填写），它会对照真实招聘信息里的岗位要求，告诉你：

- 你和哪些岗位最匹配，匹配度是多少；
- 岗位要求里，哪些你的资料里已经写了，哪些还没写；
- 这个岗位以后可以往哪里晋升、能转去哪些相近岗位；
- 接下来该补什么（需要接入 AI 模型），还能导出成 TXT 文件。

程序在你自己的电脑上运行，不需要注册账号，你的资料不会上传到这个项目的服务器。

## 它能做什么

| 功能 | 说明 | 需要 AI 模型吗 |
| --- | --- | --- |
| 职业探索 | 浏览 6 类 IT 岗位（前端、Java、C/C++、软件测试、软件实施、技术支持）的能力要求 | 不需要 |
| 手动填写资料 | 填写专业、技能、证书、素质 | 不需要 |
| 岗位匹配与推荐 | 算出匹配度，最多推荐 5 个岗位，可按城市、薪资筛选 | 不需要 |
| 成长路径 | 查看晋升路线和转岗路线 | 不需要 |
| 简历导入 | 上传 PDF / Word / TXT 简历，自动提取技能填入资料 | 需要 |
| 个人分析报告、岗位建议 | AI 根据你的资料写分析和行动建议 | 需要 |
| 导出 TXT | 把报告和建议保存成文本文件 | 不需要 |

匹配分数是程序按固定规则算出来的，不是 AI 打的分，同样的资料每次算出来都一样。AI 只负责读简历和写建议。

## 快速开始（Windows）

先装好这两样东西：

- [Python 3.12](https://www.python.org/downloads/)
- [Node.js 20 或更高版本](https://nodejs.org/)

然后打开 PowerShell，依次运行：

~~~powershell
# 1. 下载项目
git clone https://github.com/14866312/career-matching-agent.git
cd career-matching-agent

# 2. 安装（只需第一次运行，要联网）
./install.ps1

# 3. 启动
./start.ps1
~~~

浏览器打开 http://127.0.0.1:8000 就能用了。用完在 PowerShell 窗口按 `Ctrl+C` 关闭。下次使用只需运行 `./start.ps1`。

如果提示端口被占用，改用 `./start.ps1 -Port 8001`，再打开 http://127.0.0.1:8001。

## 接入 AI 模型（可选）

不接 AI 也能浏览岗位、手动填资料、看匹配结果。想用简历导入和 AI 建议，需要准备一个兼容 OpenAI 接口的模型服务（例如各家大模型平台提供的 API）：

~~~powershell
Copy-Item .env.example .env
~~~

用记事本打开 `.env`，填写三项：

- `LLM_BASE_URL`：模型服务的接口地址
- `LLM_MODEL`：模型名称
- `LLM_API_KEY`：你的密钥

保存后重新运行 `./start.ps1`。

`.env` 里是你的密钥，只留在自己电脑上，不要发给别人，也不要上传到 GitHub（项目已经设置为自动忽略这个文件）。

## 两种用法

不知道从哪开始，可以照着下面任意一种走一遍。第一次打开时也会有新手教程。

**没有简历：手动填写**

1. 在「职业探索」里点开「Java 开发工程师」，设为目标岗位
2. 在「简历与个人报告」里选择手动录入，专业填「软件工程」，技能加上 Java 和 SQL
3. 打开「匹配报告」，看匹配度、已满足和还没提到的要求，以及推荐岗位
4. 打开「成长路径」，看这个岗位以后能怎么发展

**有简历：直接导入**

1. 在「简历与个人报告」里上传简历，可以先用项目自带的 `samples/虚构简历.pdf` 试试
2. 检查自动填入的技能，删掉不准确的
3. 在「匹配报告」里按城市、薪资筛选推荐岗位
4. 生成岗位建议，复制或导出成 TXT

更详细的图文步骤见 [项目使用全过程](docs/项目使用全过程.md)。

## 匹配度是怎么算的

举个例子：某岗位必须掌握 4 项技能，你的资料里提到了其中 2 项，基础匹配度就是 2 ÷ 4 = 50%。

- **基础匹配度**：只看岗位的「必需」要求，你的资料里提到一项算一项。
- **增强匹配度**：在基础之上，把加分项、相关技能、证书和素质也算进来。相关技能（比如你会 React，岗位要求 Vue）最多只算四分之一项。
- 你多会的、岗位没要求的技能不会拉低分数；同一个技能写两遍也只算一次。
- 「资料未提及」只表示你的资料里没写，**不代表你不会**。补充资料后重新匹配即可。
- 分数反映的是你的资料和岗位要求的重合程度，不能证明真实能力。

推荐最多给 5 个岗位，默认按基础匹配度从高到低排列。按城市、薪资筛选时，月薪和日薪不会互相换算。

完整规则见 [ADR 0002](docs/adr/0002-mentioned-skills-without-confirmation-gate.md) 和 [数据字典](docs/数据字典.md)。

## 数据来源

- 岗位信息来自比赛提供的 240 条招聘样本（`competition/` 文件夹），只代表样本当时的情况，不保证现在仍在招聘。
- 岗位画像描述的是入门级要求；晋升和转岗路线是人工整理的参考建议，不保证录用、薪资或一定能转岗成功。
- `samples/` 里的简历和学生资料全部是虚构的，可以放心拿来试用。

## 隐私说明

- 你的资料只保存在当前浏览器里，刷新页面就清空。你也可以在「设置」里开启自动保存，资料只存在这台电脑的浏览器中。
- 上传的简历在服务器读完内容后立即丢弃，不保存文件，也不记录简历内容。
- 使用 AI 功能时，相关内容会发送给你自己配置的模型服务商。上传前建议删掉身份证号、电话等不必要的个人信息。
- 简历里的姓名只在当前页面显示，不参与匹配，也不会写进导出的报告。

支持的简历格式：文字版 PDF、Word（DOCX）、TXT，单个文件不超过 5MB、不超过 3 万字。扫描件、加密文件不支持（没有文字识别功能）。

常用命令：

~~~powershell
.venv/Scripts/python.exe -m pytest tests -q                    # 后端测试
.venv/Scripts/python.exe -m ruff check backend scripts tests   # Python 代码检查
npm.cmd --prefix frontend test                                 # 前端测试
npm.cmd --prefix frontend run lint                             # 前端代码检查
npm.cmd --prefix frontend run build                            # 类型检查并构建前端
.venv/Scripts/python.exe scripts/build_data.py                 # 从赛题表格重新生成岗位数据
~~~

改了前端代码后，要重新 build 并重启 `./start.ps1` 才能看到效果。开发时也可以运行 `npm.cmd --prefix frontend run dev`，在 http://localhost:5173 热更新预览（需要后端同时在 8000 端口运行）。

浏览器端到端测试：

~~~powershell
npm.cmd ci --prefix tests/browser
.venv/Scripts/python.exe tests/e2e_server.py   # 终端一：测试专用服务器（端口 8011，AI 返回固定假数据）
npm.cmd --prefix tests/browser test            # 终端二：默认使用本机 Edge，设置 PW_CHANNEL=chromium 可切换
~~~

测试服务器只把 AI 的返回换成假数据，匹配、文件解析和报告生成都是真实代码；但它不能证明真实 AI 调用可用。要检查真实模型，先正常启动服务，再运行 `.venv/Scripts/python.exe scripts/smoke_live.py`（缺少配置时退出码为 2，失败为 1，成功为 0）。

### 完整评分规则（matching-2.2）

基础分 = 资料（简历或手动填写）已提及且等级大于 0 的必需标签数量 ÷ 必需标签总数，不要求逐项确认或证据。优先项不入分母，多余学生标签不稀释，重复标签只计一次。条目只分「资料已提及」和「资料未提及（不代表不具备）」；旧数据中的等级 0 按未提及处理。

增强分中已提及的精确标签贡献为 1，不按学生自评等级折算。岗位要求等级按「了解/熟悉/熟练」映射为 1/2/3（无明确文字默认 2），只用于展示。资料中提及的关联技能最多贡献 0.25，多个不叠加，不代表已掌握。证书与素质按是否提及计 0/1。空维度显示不适用；全部无要求则不可计算并排除推荐。

推荐最多 5 个典型岗位，默认基础分排序，同分按岗位 ID。城市、薪资条件针对实际样本记录；同计薪周期区间重叠，日薪/月薪不换算。无薪资条件时保留未知薪资。技能筛选要求全部所选标签出现。候选不足 3 个时如实展示。

其他说明：

- 每次 AI 请求最多等 45 秒，遇到网络错误、429 或 5xx 会自动重试一次。
- 需要独立的干净 Python 环境时，运行 `./install.ps1 -VenvPath .venv-acceptance -SkipFrontend`，启动时使用相同的 `-VenvPath`。
- 最终验收状态和已知限制以 [docs/acceptance/后端测试.txt](docs/acceptance/后端测试.txt) 为准。
- 早期示例中曾出现过一个真实密钥，已经删除并应在服务商处作废，不要使用。
- 每次推送和 PR 都会由 GitHub Actions 自动运行后端与前端检查。
