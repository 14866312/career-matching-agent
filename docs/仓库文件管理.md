# 仓库文件管理

GitHub 保存能让别人理解、安装、运行和验证项目的文件。本地文件夹还会有运行环境、缓存和个人工作材料，因此两边的目录数量通常不同。同步应核对 Git 跟踪的文件及提交，不需要把整个电脑文件夹上传。

## 公开内容

| 文件或目录 | 保留原因 |
| --- | --- |
| `backend/app/`、`frontend/src/` | 应用代码和匹配规则 |
| `backend/data/career-data.json` | 启动所需岗位数据；由脚本生成并提交，便于下载后直接运行 |
| `scripts/`、`tests/` | 数据重建、虚构样例重建、模型检查和自动化验证 |
| `requirements*.txt`、`requirements.in`、两份 `package-lock.json` | 安装依赖并复现已验证版本；PDF 样例工具依赖独立保存 |
| `install.ps1`、`start.ps1`、构建配置 | Windows 安装、启动和开发入口 |
| `.env.example` | 不含真实密钥的模型配置模板 |
| `.github/` | 三项 CI 与 Dependabot 配置 |
| `samples/` | 可公开的虚构学生资料与简历，供演示和测试 |
| `competition/` | 用户已确认公开的只读赛题原件；版权不属于项目 MIT 许可 |
| `docs/` | 使用指南、数据说明、接口契约、ADR、工作日志和精选验收证据 |
| `AGENTS.md`、`CLAUDE.md`、`CONTEXT.md`、`.claude/launch.json` | 可复用的项目协作约定、领域术语和相对路径启动配置 |
| `README.md`、`LICENSE`、Git 配置文件 | 项目入口、授权和公开文件边界 |

生成文件需要按用途判断：岗位 JSON 和依赖锁文件是运行、复现所需，应提交；`frontend/dist/` 是安装时重建的产物，应忽略。

## 只留本地

| 文件或目录 | 处理方式 |
| --- | --- |
| `.env`、`.env.local` 等 `.env.*` | 忽略，真实密钥只在本机配置；`.env.example` 除外 |
| `.venv*/`、任意层级的 `node_modules/` | 忽略，由安装命令创建 |
| `frontend/dist/`、Python 缓存、Ruff/pytest 缓存 | 忽略，由构建或检查命令创建 |
| 测试结果、覆盖率、日志、`tmp/`、`temp/` | 忽略；需要公开的证据先审查再选入文档 |
| `.claude/` 私有设置、`.vscode/`、`.idea/` | 忽略；Claude 仅共享 `launch.json` |
| `本地资料/` | 忽略，存放需求、工单、设计参考、笔记、PPT、Word、工具配置及历史工作资料 |
| 真实简历、个人联系方式和私人交付材料 | 放入 `本地资料/`；不要用真实数据替换公开虚构样例 |

2026-10-05 已将两份旧任务/代理记录、带机器路径的后端原始日志以及两份重复/中间数据构建记录转入本地归档。五份文件均核对 SHA256 与原件一致；公开保留 `数据构建-最终.json`、`数据可复现性.json` 和相应验收汇总。

移出当前版本不会删除 Git 历史。今后若误提交真实凭据，必须在服务商处作废或轮换，再按实际情况处理历史；仅添加忽略规则不能撤回已经提交的内容。

## 日常检查

在项目根目录用 PowerShell 执行：

~~~powershell
git status --short                 # 查看本次待提交内容
git status --short --ignored       # !! 表示只留本地的忽略文件
git ls-files                      # 查看 Git 跟踪的公开文件
git check-ignore -v .env.local     # 检查某个文件为什么被忽略
git fetch origin --prune           # 刷新远端状态，清除已删除分支的本地引用
git diff --stat main origin/main   # 核对两边已提交的文件变化
git rev-list --left-right --count main...origin/main
~~~

最后一条命令的两个数字分别表示本地独有和远端独有的提交数，`0 0` 表示提交一致；还需确认 `git status --short` 没有未提交变更。`.gitignore` 只影响尚未跟踪的文件。已经提交的私有文件应先保留本地副本，再从 Git 跟踪范围移除。

浏览器检查默认会改写 `docs/acceptance/`。日常重跑先设置 `E2E_OUTPUT_DIR` 为 `tmp/` 下的目录；需要刷新公开证据时再审查选用，避免每次运行都提交截图、报告和时间戳。
