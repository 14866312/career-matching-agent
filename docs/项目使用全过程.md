# 项目使用全过程

本文按真实界面和当前代码，记录从安装启动到整理档案、查看匹配、采取行动并保存本机进度的完整过程。应用运行在本机，面向演示与自我探索；没有账号或数据库，个人资料只保存在当前浏览器（若启用自动保存），不会上传到本项目服务端。

## 流程总览

~~~mermaid
flowchart TD
    A[安装依赖并启动本机服务] --> B[打开页面并长按启动核心]
    B --> C{先选岗位或先建档}
    C -->|选岗位| D[浏览岗位并设为目标]
    C -->|先建档| E{准备能力资料}
    D --> E
    E -->|手动录入| F[填写背景、能力等级和证据]
    E -->|导入简历| G[上传简历并生成临时候选]
    G --> H[逐项接受或跳过后确认合并]
    F --> I[可选：生成 AI 能力摘要]
    H --> I
    I --> J[确认能力档案]
    J --> K[计算匹配并查看岗位推荐]
    K --> L[可选：生成职业建议并复制或导出 TXT]
    D --> M[随时查看职业成长路径]
    K --> M
~~~

简历解析、AI 能力摘要和职业建议需要配置真实模型服务。没有模型配置时，仍可浏览岗位和路径，也可以手动建立并确认画像、查看确定性匹配结果；简历解析与 AI 文字建议暂不可用。

## 1. 安装并启动

在 Windows PowerShell 中进入项目根目录。首次使用需要 Python 3.12、Node.js 20+、npm 和网络连接：

~~~powershell
./安装环境.ps1
Copy-Item .env.example .env
~~~

如果准备使用真实模型，在本机编辑 <code>.env</code>，填写可信服务商提供的 <code>LLM_BASE_URL</code>、<code>LLM_MODEL</code> 和 <code>LLM_API_KEY</code>。示例文件里的域名与密钥只是占位值。不要把密钥放进聊天或提交到版本库。也可以先不配置模型，直接启动手动匹配流程。

~~~powershell
./启动服务.ps1
~~~

浏览器打开 <code>http://127.0.0.1:8000</code>。若端口被占用，可运行 <code>./启动服务.ps1 -Port 8001</code>，再打开 <code>http://127.0.0.1:8001</code>。服务只绑定本机回环地址。完成使用后，在运行服务的 PowerShell 窗口按 <code>Ctrl+C</code> 停止。

之后再次使用通常只需启动脚本，无需重新安装依赖。修改前端代码后，先在 <code>frontend</code> 目录执行 <code>npm.cmd run build</code>，再重启服务。

## 2. 进入职业探索

首次打开会显示启动动画。按住页面中央的核心按钮，直到动画完成并进入主界面。

主导航包含四个区域：

- **职业探索**：搜索和查看岗位画像。
- **能力档案**：手动填写或导入简历，整理并确认个人能力。
- **匹配报告**：计算岗位匹配、设置筛选条件、生成和导出建议。
- **成长路径**：查看纵向晋升和横向转岗路线。

主导航下方的流程栏显示目标岗位、能力档案、匹配结果和行动建议的状态，并提供当前可执行的下一步。目标岗位可以跳过；点击成长路径可随时进入可选页面。四个页面仍可自由切换，浏览器前进和后退也会切换当前页面。

首次进入主界面时，可以选择是否在当前浏览器自动保存。选择启用后，档案、目标岗位、当前页面和已保存的成长路径会随操作自动保存；关闭后仍可继续当前会话，但本次不读取旧草稿。

顶部的 **AI 模型配置** 可在应用内选择 DeepSeek 或 OpenAI 兼容接口，填写地址、模型、适配器和密钥，保存后点击 **测试连接**。测试只发送一条不含个人资料的短请求。通过界面保存的配置只作用于当前运行中的服务进程；若希望服务重启后仍保留，请把配置写入本机 <code>.env</code>。

## 3. 浏览岗位并选择目标

在 **职业探索** 页面，可以按岗位名称、方向或技能关键词搜索。点击岗位卡片打开详情，查看岗位简介、核心技能、证书、通用素质、优先项和历史招聘样本；岗位详情也会显示要求等级的整理依据与样本引用。点击 **设为目标岗位**，即可把该岗位设为个人意向岗位。

岗位可以先选，也可以稍后再选。点击 **设为目标岗位** 后会进入能力档案继续整理。单独更换目标岗位会保留档案确认，但会让已有匹配和报告过期；请刷新匹配后再生成新建议。筛选条件只改变岗位推荐，不会撤销档案确认。

岗位画像来自项目收集的赛题招聘样本，目标是整理初级能力基线。样本不保证仍在招聘，画像也不代表所有雇主的统一硬性要求。

## 4. 建立能力档案

进入 **能力档案**，在 **导入现有简历** 与 **手动录入资料** 之间选择。两种方式可以配合使用；导入不会清空已有资料。

### 手动录入

切换到 **手动录入资料**，填写专业、意向城市、目标岗位和项目／实习经历。然后在技能、证书和通用素质区域逐项添加能力。输入框会提示岗位标签字典中的名称和别名；不在字典中的自定义标签会标记为 **未入字典**，可能无法与岗位要求匹配，优先使用字典中的规范标签。

技能等级为 0–3。证书和通用素质按“具备／不具备”记录。对准备声明为具备的能力，展开该行的 **证据**，填写真实经历中能支持该项能力的原文或事实，例如课程项目、实习任务或作品说明。证据是用于计算的依据，不等于外部认证。

### 导入简历

切换到 **导入现有简历**，选择文本型 PDF、DOCX 或 TXT 文件。单文件最大 5 MB，提取文字最多 30,000 字符，PDF 最多 50 页；扫描图片、加密、损坏或没有足够可提取文字的文件不受支持，也不会进行 OCR。仓库中的 <code>samples/虚构简历.pdf</code>、<code>.docx</code> 和 <code>.txt</code> 是虚构演示样例。

解析会把简历文字交给当前配置的模型，生成姓名、经历、技能、证书和素质等临时候选。每项都要选择 **接受** 或 **跳过**，然后点击 **确认并合并已接受项** 才会写入档案。候选列表只存在当前会话，刷新或离开后不会恢复；解析失败时，已有手动内容保持不变。

合并时，档案中已有的非空专业、经历、标签、等级和证据优先保留，界面会提示存在差异的冲突。新加入的能力保持 **待确认**，不会因接受简历候选而自动变成已核验能力。简历姓名只存在当前会话，不参与匹配、报告或本机草稿。

上传前请删去不必要的身份信息。应用不保存简历文件或正文日志，但模型处理会把相关输入发送给你配置的服务商。

## 5. 生成、核对并确认画像

能力档案底部的 **生成能力画像** 会请求模型整理画像摘要、优势和待提升内容。它是可选步骤，不能替代人工核对；无模型配置时可跳过。若生成失败，页面会保留输入并提供重试。

确认前逐项检查：

1. 专业、经历、意向城市和目标岗位是否正确。
2. 每个能力标签是否对应真实经历，标签和熟练度是否合适。
3. 正向能力是否填入了相应证据；不具备的项目是否设为 0。
4. AI 摘要和已经审核合并的简历内容是否准确。

准备好后点击 **确认完整画像**。这会确认整份档案，让它可以用于匹配；它不会替你核实证据真假。对必需要求，只有已确认、等级大于 0 且有证据的能力才算满足。缺少证据或尚未确认的项目仍会列为待确认；明确选择 0 的项目会列为差距。没有技能的空画像也可以确认，用来查看当前岗位的缺口。

档案页分别列出待确认、缺少证据和已确认不具备的项目；岗位要求中尚未录入的项目会在匹配待办中显示。示意雷达图用于整理参考，不是岗位匹配分，也不再用固定经历字数表示完成度。修改档案内容会撤销整份确认并使匹配和报告过期；单独切换目标岗位会保留确认，但同样会使匹配和报告过期。

## 6. 查看匹配与筛选推荐

确认画像后进入 **匹配报告**，系统会自动计算推荐。即使没有目标岗位，也可以查看岗位推荐；设定目标后，目标岗位即使不在前五个推荐中也会单独展示。页面可以查看基础匹配分、增强参考分、各能力维度、已满足项、明确差距和待办。

- **基础分**统计有证据、已确认且等级大于 0 的必需项覆盖率；技能达到更高岗位等级要求不会改变基础分。
- **增强分**进一步反映技能等级与岗位要求等级的比例。证书和通用素质按是否具备计算；有证据的关联技能可以提供有限参考贡献，但不代表已掌握，也不改变基础分。
- **优先项**只作补充建议，不计入基础分或增强分。

展开 **调整岗位筛选条件**，可以设置城市、薪资下限／上限、按月或按天计薪、必须包含的技能，并选择按基础分或增强分排序，然后点击 **应用筛选**。多个技能条件要求岗位同时包含所有指定标签。薪资和城市筛选基于岗位关联的招聘样本；月薪和日薪不会互相换算。未设置薪资范围时保留薪资未知的样本，启用薪资范围后未知或计薪周期不同的样本不能满足该条件。

系统最多展示 5 个符合条件的推荐岗位。如果个人意向目标不在前 5 名，页面会额外单独计算并展示它。点击其他岗位卡片即可切换当前分析对象；切换后旧建议会清除，需要为新岗位重新生成。

匹配待办按岗位必需项优先排列：尚未填写的项目可直接跳到对应能力录入位置；待确认或缺证据项目会定位到档案对应标签并展开证据编辑；已确认不具备的项目可查看学习建议或进入成长路径。画像编辑后先重新确认，再点击 **刷新匹配结果**；仅更换目标岗位时档案确认仍有效，直接刷新即可。服务端的数据或算法版本变化后也需要刷新。

## 7. 生成并导出职业建议

选定要分析的岗位后，点击 **生成 AI 深度建议**。后端会按当前画像重新计算分数和匹配事实；AI 只负责生成契合度文字、学习方向和行动建议。模型没有配置、网络不可用或返回内容不符合要求时，页面会显示错误，可修正配置后重试。

检查建议与自身情况是否相符后，可以点击 **复制报告** 或 **导出 TXT**。两种操作使用服务端返回的同一份报告正文。画像、目标岗位或服务端版本改变后，旧报告会标记失效并禁止复制或导出；画像内容变化时需重新确认并刷新匹配，目标岗位变化时刷新匹配即可，然后生成新报告。页面会说明过期原因和下一步。

建议用于辅助规划，不保证录用、薪资或岗位转换。历史样本也不应当作当前招聘信息。

## 8. 查看成长路径并结束使用

进入 **成长路径**，默认聚焦目标岗位（如果没有目标岗位则使用可用路径）；你手动切换后会沿用自己的选择。点击阶段卡片或路线可查看可迁移能力、待补差距和建议活动。点击 **保存当前路径** 会保存当前聚焦岗位及选中的路线，并显示保存时间；需要时可以清除已保存路径。

### 本机草稿、关闭与清除

启用自动保存后，以下信息保存在当前浏览器的本机存储中，并在刷新或重新打开页面时恢复：能力档案及确认状态、目标岗位、当前流程页面，以及已保存的成长路径。草稿带有格式版本；若损坏或版本不兼容，页面会提示无法恢复并从空白会话继续。

本机草稿**不包含**简历姓名、尚未审核的简历候选、原始简历文件、AI 报告或模型密钥。未审核候选只在当前页面会话内暂存，刷新后需要重新导入。自动保存开关可随时关闭；关闭后本次不会读取旧草稿，已有草稿会保留到你手动清除。浏览器存储不可用或写入失败时，页面会提示原因，当前会话仍可继续使用。

点击任意页面上的 **清除本机草稿并重置流程** 会删除当前浏览器中的草稿，并重置档案、流程位置和保存的成长路径；不会清除服务端或模型配置。需要保留职业建议时，请先点击 **导出报告TXT**。完成使用后，在服务终端按 <code>Ctrl+C</code> 停止服务。

## 故障时怎么继续

| 现象 | 处理方法 |
|---|---|
| 页面打不开或显示无法连接后端 | 检查 PowerShell 中的服务是否仍在运行，并使用启动时对应的端口访问。 |
| 岗位列表或详情加载失败 | 点击页面的重新加载；若持续失败，重启本地服务并检查终端错误。 |
| 简历、画像摘要或建议提示模型未配置 | 在 **AI 模型配置** 中填写并保存后测试，或在本机 <code>.env</code> 配置并重启服务。手动匹配不要求模型。 |
| 简历无法读取 | 确认文件是可复制文字的 PDF、DOCX 或 TXT，未加密且没有超过大小、页数和文字限制；也可手动填写。 |
| 匹配或报告提示画像未确认／结果失效 | 返回能力档案核对并再次确认，再刷新匹配结果。 |
| 关闭自动保存后看不到旧档案 | 自动保存关闭时不会读取旧草稿；重新启用即可恢复，或检查是否已清除草稿。 |
| 本机草稿无法保存或恢复 | 确认浏览器允许本地存储；存储不可用时可继续当前会话，但刷新后无法恢复。 |
| 自定义能力没有计入岗位匹配 | 使用 <code>/api/tags</code> 对应的字典标签或别名，并为正向能力补充证据。 |
