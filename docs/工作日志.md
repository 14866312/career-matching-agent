## 工作流程

- `main` 有分支保护：必须走 PR，后端、前端和浏览器三项 CI 通过后才能合并，禁止 force push 和删除分支。浏览器 CI 使用模拟模型 JSON，不作为真实模型验收证据。管理员不受限，但仍按 PR 流程走。
- 每次改动：从 `main` 新建分支 → 提交 → push → `gh pr create` → 等 CI 通过 → 合并并删除分支 → 本地 `git pull`。
- 提交信息用 Conventional Commit（`feat(frontend): …`、`fix(deps): …`）；PR 标题和正文用中文。
- 用户刚开始学 GitHub，操作后用中文解释做了什么、为什么这样做。

## 依赖与 Dependabot

- `.github/dependabot.yml` 每月检查 pip、npm（frontend）和 GitHub Actions；前端大版本升级被忽略。
- 多个 Dependabot PR 同时出现时，合并成一个分支统一升级，再关闭原 PR。改 Python 版本时要同时改 `requirements.in` 和 `requirements.txt`，并且保留 `requirements.txt` 里 Windows 需要的 `colorama`、`tzdata`（Dependabot 在 Linux 上生成的锁文件会把它们删掉）。
- `frontend/package-lock.json` 使用 registry.npmmirror.com 镜像，保持不变。
- 待办：React 19、Vite 8、ESLint 10、vitest 5、@vitejs/plugin-react 6 的大版本迁移还没做，需要单独开分支并改代码。
