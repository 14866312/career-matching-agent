# 基础匹配分只看资料是否提及，取消人工确认与熟练度折算

## 背景

matching-2.1 要求每个能力条目“已确认、有证据且等级 > 0”才计满足，整份画像还须 StudentProfile.confirmed 为真，匹配、推荐、报告 API 才放行（PROFILE_UNCONFIRMED）。演示中暴露三个问题：用户需逐项确认并补证据，简历路线步骤过多；学生自评的 1–3 级熟练度不可核实，却能改变增强分；等级 0 被当作“已确认不具备”，与“资料未提及不等于不具备”的原则冲突。

## 决策

- 基础匹配分 = 资料（简历或手动填写）已提及且 level > 0 的必需标签数 ÷ 必需标签总数。不再要求 confirmed 或 evidence。
- 增强分中，已提及的精确标签贡献为 1，不按学生等级与岗位要求等级折算；关联技能仍最多贡献 0.25、不叠加。
- 条目状态只有“资料已提及（satisfied）”和“资料未提及（pending / not_provided）”。等级 0 的旧数据按未提及处理，不再产生“明确差距”。
- 移除 PROFILE_UNCONFIRMED 门槛：未确认档案也可调用匹配、推荐和报告。Ability.confirmed、StudentProfile.confirmed 字段保留，只为兼容旧草稿。
- 简历解析结果直接合并进档案（前端 resumeImport.ts）：替换上一次简历导入的条目，保留用户手动填写的专业、经历和能力，不再逐项审核候选。条目带 source 字段区分 resume / manual。“简历摘录”只用于核对，不是提交门槛。姓名仍只作为会话姓名单独保存，不并入 StudentProfile（ADR 0001）。
- ALGORITHM_VERSION 升级为 matching-2.2，旧结果按指纹失效。

## 影响

- 分数语义变为“资料覆盖度”，不是能力证明；界面与报告统一使用“资料已提及 / 资料未提及（不代表不具备）”。
- 报告 TXT 不再有“明确差距”“待确认”两行，改为上述两行。
- 模型输出不参与评分的原则不变；ADR 0001 的姓名边界不变。
- 用户若在简历中虚报技能，会直接计入基础分。这被视为演示原型可接受的风险，在界面与报告中说明“资料未提及不代表不具备、提及不代表已核实”。

## 考虑过的替代方案

- 回退到 matching-2.1（保留逐项确认与证据门槛）：口径更严谨，但操作链长，且等级 0 仍被当作能力缺失。
- 保留简历候选逐项接受/跳过的审核列表：更可控，但与取消确认门槛的目标重复，操作负担回到用户。
- 折中：取消整份画像确认门槛，但保留逐项确认才计分：减少一次拦截，但仍需逐项操作，且无法解决自评等级不可靠的问题。
