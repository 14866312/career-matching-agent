Lesson 0007 · 项目整体认识

怎样确认项目能运行、能计算、能交付？

这个项目的验证分成数据、后端、前端、浏览器和真实 AI 服务几层，每层回答的问题不同。

先安装和启动

Windows PowerShell 下，先进入项目目录，运行 ./安装环境.ps1。然后复制 .env.example 为 .env，按需填写可信模型供应商配置。

启动时运行 ./启动服务.ps1，默认打开 http://127.0.0.1:8000。端口冲突时可以使用 ./启动服务.ps1 -Port 8001。

启动脚本会检查 Python 环境、前端生产构建和主要依赖。前端代码修改后，需要在 frontend 目录重新执行 npm.cmd run build，再重启服务。

第一层：数据构建验证

运行 .venv/Scripts/python.exe scripts/build_data.py，确认岗位数据可以从原始资料稳定生成。数据测试还会检查标签、重复岗位、版本和可复现性。

这层验证的是：运行时的 career-data.json 是否正确生成，输入资料变化是否真正传到了运行时数据。

第二层：后端和前端测试

后端运行 .venv/Scripts/python.exe -m pytest tests -q，覆盖数据、匹配、API、简历解析和 AI 契约。当前项目此前验证结果为 305 passed。

前端运行 npm.cmd --prefix frontend test，验证组件和交互逻辑。当前项目此前验证结果为 21 passed。

前端生产构建运行 npm.cmd --prefix frontend run build，它会先做 TypeScript 检查，再生成可被后端托管的 dist 文件。

第三层：浏览器验收

浏览器验收使用 tests/browser 中的自动化脚本，覆盖手动填写、简历导入、确认画像、推荐、生成报告和导出 TXT 等完整用户路线。

测试专用服务器由 tests/e2e_server.py 启动，默认地址是 http://127.0.0.1:8011。它只替换模型响应，不替换匹配、验证、文件解析和报告组装。

真实服务和模拟服务的区别

浏览器自动化可以证明页面流程和本地业务逻辑，但不能代替真实模型供应商验证。真实服务检查使用 scripts/smoke_live.py，需要本机配置可用的模型服务。
