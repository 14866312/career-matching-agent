Lesson 0003 · 项目整体认识

目录应该怎么读？

不要把项目目录看成一堆文件。可以按“界面、后端、数据、脚本、测试、文档”六类来记。

先看项目根目录

frontend：用户看到的页面和交互。
backend：API、数据模型、匹配、简历解析和 AI 调用。
scripts：构建岗位数据、制作样例、运行冒烟检查。
tests：验证数据、业务逻辑、API、AI、简历和浏览器流程。
docs / competition / samples：项目说明、竞赛资料、演示输入和验收产物。

前端：把功能组织成用户页面

frontend/src/App.tsx 是总入口，定义四个主要区域：岗位浏览、我的能力、职业路径、匹配与建议。

components/JobsTab.tsx、ProfileTab.tsx、PathsTab.tsx 和 MatchesTab.tsx 分别负责各页面区域。api.ts 统一发送请求，types.ts 描述前后端共享的数据形状，report.ts 负责把报告结果整理成可导出的文本。

后端：把一次操作变成业务结果

backend/app/main.py 是 API 入口。它负责路由、输入校验、确认状态拦截，以及把请求交给具体模块。

  • models.py：定义学生画像、能力、岗位匹配请求等数据契约。
  • data.py：读取并缓存岗位数据集。
  • matching.py：确定性计算匹配分、差距和岗位推荐。
  • resume.py：从上传的 PDF 或 DOCX 中提取文本。
  • llm.py：调用 AI 做简历整理、能力画像和学习建议。

数据和脚本：提供系统运行所需的材料

backend/data/career-data.json 是运行时读取的岗位数据集。scripts/build_data.py 负责把原始资料整理成这个结构化数据集。

samples/ 存放演示用简历，make_samples.cjs 和 make_sample_pdf.py 用来生成样例文件。修改岗位原始资料或数据规则时，应该优先检查数据构建脚本和数据审核文档。

遇到问题时的查看顺序

先看前端页面 → 再看 API 入口 → 再看对应业务模块 → 最后看数据和测试。

例如“匹配分不对”，通常沿着 MatchesTab.tsx → /api/matches → matching.py → career-data.json 这条路径排查。
